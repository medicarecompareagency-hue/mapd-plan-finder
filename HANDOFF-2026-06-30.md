## Part 1 — Shipped this session: Segment-aware SB fix

### The bug (and the important correction)
Searched Perry County, MS / MAPD; #1 was H4407-30 (HealthSpring), but its SB service area = George/Hancock/Harrison/Jackson/Stone — Perry not listed. **Root cause: CMS publishes a SEPARATE SB per (contract, plan, segment); segments differ in service area AND benefits. The DB stored ONE SB per planId.**

**Correction to the premise:** Perry IS legitimately in H4407-30's service area — via **segment 2** (the plan has 3 segments). Plan/county membership and on-card numbers were CORRECT (Perry MOOP $5,200 = seg 2). Only the linked SB doc was the wrong segment's (seg 1). **Do NOT "fix" by removing plans from counties — that deletes valid coverage.**

### Scope (live audit, 18 licensed states + contracted carriers)
58 multi-segment plans, 91 segments, ~1,730 county-rows. Single-segment plans (~96%) unaffected. By carrier (segments): HealthSpring 38, UnitedHealthcare 22, Humana 19, Devoted 8, Wellcare 4. **All DONE — 0 remaining.**

### What was built
- **Schema:** `Plan.segmentId` (this row's CMS segment, from `.cms-import-tmp/pbp-2026/PlanArea.txt`) + `Plan.sbSegmentId` (which segment the stored SB represents). Populated by `scripts/backfill-segment-ids.js`.
- **Gate:** `/api/plans` `isSbSegmentMismatch()` — when `segmentId !== sbSegmentId`, null `sbPdfUrl` + flag `sbSegmentMismatch`; UI shows segment-correct medicare.gov link ("Segment SB on medicare.gov"). `planCompareUrl` is now segment-aware.
- **Linking:** `scripts/link-segment-sbs.js` reads `[{planId,seg,url}]`, sets `sbPdfUrl` + `sbSegmentId = segmentId` + `sbPdfSourceFilename` -> opens the gate.
- **Coverage:** 91/91. HealthSpring + Humana via deterministic URL patterns; Devoted gate-opened (Devoted = ONE SB per plan, covers all segments); UHC via CDN + alphadog; Wellcare via Centene DAM. Final 13 (UHC opaque-docid AARP + Wellcare) finished by Claude Code pipeline, re-hosted to Vercel Blob.

### Carrier SB-URL patterns cracked (reuse for AEP / re-imports)
- **HealthSpring (deterministic):** `content.medicareadvantage.com/2026/Healthspring_sb-h{contract}-{plan3}-{seg3}_2026_SB_SF20260211.pdf`
- **Humana (deterministic):** `content.medicareadvantage.com/2026/Humana-H{contract}{plan3}{seg3}SB26pdf-2026-SF20251001.pdf`
- **UHC:** alphadog serves the PDF directly — `uhc.com/medicare/alphadog/{docid}` (AARP), `uhc.com/communityplan/alphadog/{docid}` (D-SNP). CDN `content.medicareadvantage.com/2026/UHC-{AA|CS|UH}{ST}26{HP|LP}{docid}-...-H{contract}{plan3}{seg3}-SB-...pdf` has an OPAQUE per-(plan,segment) docid.
- **Wellcare:** Centene DAM (NOT content.medicareadvantage.com) — `wellcare.com/-/media/pdfs/medicare-2026/{st}/sb/{docid}_2026_{ST}_SB_{TYPE}_{num}ENG_M.ashx`

## Method / guardrails (project law — unchanged)
- Verify-first (acquire + confirm SB before writing) + fill-only (never overwrite a non-zero value; one exception: correct a confirmed stale-2025 value from the 2026 SB).
- DB = Neon. `makePrisma()` from `scripts/prisma-client.js` only (auto-adds `?pgbouncer=true`; raw client -> Postgres 42P05). Additive `prisma db push` only.
- pdfplumber for SB tables. Durability via `reapply-sb-truth.js`. No raw `Uint8Array -> Blob` in committed scripts.
- OneDrive mount truncates large Edit/Write -> do risky writes via a throwaway Node script; throttle; checkpoint; resume. `vercel --prod` from a SECOND PowerShell window.
- Per-carrier food/OTC extractors: `fill-uhc-foodcard-from-sb.js` (UHC/Wellcare), `scripts/extract-devoted-foodcard.js` (Devoted), Aetna Extra-Supports-Wallet script. Humana + HealthSpring still need new extractors.

## Backup / deploy workflow
- Backup: `git add -A; git commit -m "..."; git push` (repo medicarecompareagency-hue/mapd-plan-finder).
- Deploy: `vercel --prod` from a second PowerShell window (live mcaplanfinder.xyz). Independent of backup.
